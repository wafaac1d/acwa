# Продукт

Пользователь один: владелец установки. Регистрации нет.

## Сценарий MVP

1. Подключить аккаунт Threads или, в demo, демонстрационный аккаунт.
2. Создать кампанию: тема, стиль, ограничения, расписание, режим публикации.
3. Сгенерировать пробный пост, поправить текст и убедиться, что он проходит лимит Threads.
4. Включить расписание. Пока кампания на паузе или в архиве, новые слоты не создаются.
5. В ручном режиме пост ждёт одобрения. В автоматическом после успешной проверки уходит на публикацию.
6. Смотреть очередь, историю, ошибки и попытки.

Пробная генерация работает и у приостановленной кампании.

## Режимы

По умолчанию ручное подтверждение. Автоматический режим публикует только если кампания включена, текст прошёл проверку и запрос ещё не был неоднозначным.

Одобрение после наступившего времени публикует пост сразу. Без одобрения просроченный пост остаётся в очереди.

## Политика пропущенных слотов

Окно допуска по умолчанию 15 минут. После простоя создаётся не больше одного слота, и только если он попал в это окно. Более ранние слоты записываются как пропущенные. Пауза сдвигает курсор расписания на текущий момент и отменяет ещё не отправленные автоматические слоты. Пока в кампании есть незавершённый пост расписания, следующий слот не создаётся.

Изменение расписания отменяет неотправленных будущих слотов. Уже одобренный, но не отправленный пост возвращается на проверку.

## Границы

В MVP есть только текстовые посты. Нет медиа, ответов, лайков, подписок и удаления постов в Threads. Нет нескольких пользователей и ролей.

Вход закрыт паролем из `ACWA_AUTH_TOKEN`. Без верного пароля интерфейс не открывает кампании, а API отвечает 401. Это общий пароль одного владельца. Для доступа из сети его нужно заменить на длинный случайный и не публиковать.

## Приёмка demo

Кампания сохраняется в PostgreSQL, пробный пост генерируется локально, текст редактируется, одобрение ставит публикацию в очередь, worker после нового процесса публикует mock-результат с `is_demo_publication=true` и пустым permalink. Пауза не создаёт новые автоматические посты. Секреты не попадают в ответы API.
